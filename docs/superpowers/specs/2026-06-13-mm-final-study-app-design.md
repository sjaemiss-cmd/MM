## 1. 목표

마케팅관리(류상희 교수) **기말고사(6/16)** 대비 모바일 퍼스트 학습앱.
기존 중간고사 앱(`mm-study.html`)을 baseline으로, **퀄리티를 대폭 상향**하고
**Supabase 로그인 + 사용자별 진도 동기화**를 추가한 기말 버전을 제작한다.

핵심 차별점(중간 → 기말):
1. localStorage → **Supabase**(다중 사용자, 기기 간 동기화)
2. **아이디/비번 간단 로그인** + 사용자별 진도
3. 디자인·UX **품질 대폭 상향**
4. 범위 **T5~T9**(마케팅 조사 + 마케팅 믹스 4P)

## 4. 기술 아키텍처

- **빌드 없는 정적 웹앱** + **Supabase JS(CDN)**. GitHub Pages 워크플로우 유지.
- 진입점 **`index.html`**(루트 URL이 기말앱). 기존 `mm-study.html`(중간)은 보존.
- **콘텐츠 = repo 정적 JSON**(검수·버전관리·빠른 로드). **Supabase = 사용자 데이터만**.
- 코드 구성(단일 거대 파일 지양, 그러나 빌드 없음):
  - `index.html` — 앱 셸/화면 마크업
  - `app.js` — 로직(모듈, ES module import 가능)
  - `styles.css` — 디자인 시스템
  - `data/questions.json` — 문제은행(T5~9)
  - `data/theory.json` — 이론 카드(T5~9)
  - `data/cases.json` — 사례 포인트 카드
  - `supabase.js` — Supabase 클라이언트 + 인증 + 동기화
  - `manifest.json` / `sw.js` — PWA(기말용 갱신)

## 5. 데이터 스키마

**문제(question)** — 기존 스키마 유지(앱 재사용성):
```json
{ "id": 601, "topic": 6, "section": "6.1", "type": "mc|blank",
  "q": "질문(빈칸은 ______)", "options": ["①…","②…"], "answer": 0,
  "accept": ["허용답1","허용답2"], "explain": "해설", "stars": 5,
  "case": "stanley"  // (선택) 사례 연계
}
```
- `mc`: `answer`=정답 인덱스(0-base 또는 기존 규칙), `options` 필수.
- `blank`: `answer`=정답 문자열, `accept`=허용 표기 배열(매칭 관대).
- `stars`: 출제예상도 5(필수)~3(보통). 빈칸은 기본 5.

**이론(theory)**:
```json
{ "t": 6, "s": "6.1", "st": "섹션명", "title": "카드 제목",
  "md": "- 마크다운, **`코드`**=빈칸 토글" }
```

**사례(case)** — 신규:
```json
{ "id": "chipotle", "topic": 9, "title": "Chipotle 가격 전략",
  "article": "기사 요약", "points": ["핵심포인트1","핵심포인트2"],
  "concepts": ["가치기반가격","가격민감도"] }
```

## 6. Supabase 설계

- **연결:** 사용자가 제공하는 프로젝트 URL + anon key를 `supabase.js`에 설정(공개 anon key는 노출 가능, 보안은 RLS로).
- **인증:** Supabase Auth(email/password). 사용자는 **아이디/비번**만 입력 →
  내부적으로 `<아이디>@mm.local` 합성 이메일로 가입/로그인. 이메일 확인 비활성화.
- **테이블:**
  - `user_state(user_id uuid pk, state jsonb, updated_at timestamptz)`
    — 앱 상태 객체(진도/오답/세션) 통째 동기화. 최소 리스크.
  - `quiz_results(id, user_id, mode, score, total, taken_at)` — 점수 이력.
- **RLS:** 두 테이블 모두 `auth.uid() = user_id`인 행만 select/insert/update.
- **동기화 전략:** localStorage를 1차 캐시로 쓰고(오프라인 동작), 로그인 시 서버 상태 pull,
  변경 시 debounce하여 push. 충돌은 `updated_at` 최신 우선(단일 사용자 다기기 가정).

## 7. 학습 기능 (모드)

기존 5모드 유지 + 강화 + 신규 1:
1. **이론 학습** — 토픽·섹션별 개념 카드, 빈칸 토글, 전체 공개.
2. **전체 학습** — T5~9 순서대로.
3. **토픽별 학습** — 토픽 선택.
4. **모의고사** — 기말 형식 ~55문항(선다 85%+주관 15%), 채점·결과.
5. **빈칸만 학습** — 주관식 빈칸 집중.
6. **오답 복습** — 틀린 문제만.
7. **사례 포인트(신규)** — Stanley/Chipotle 등 사례별 핵심포인트·연계개념.
- 공통: **이어풀기**(세션 저장/복원), 별점(출제예상도) 필터.

## 8. 품질 업그레이드(중간 대비 "발전")

- **디자인 시스템**: 정제된 타이포·여백·색, **다크모드**, 카드/그림자/마이크로 인터랙션.
- **대시보드 홈**: 전체 진도율, **토픽별 숙련도 바**, 약점 토픽, 연속 학습/최근 학습.
- **퀴즈 UX**: 부드러운 전환·정오답 피드백, 빈칸 입력 편의, 해설 즉시 노출.
- **부가**: 검색, 즐겨찾기(북마크), "오늘의 복습".
- **대표 신기능**: 로그인 기반 **기기 간 진도 동기화(폰↔PC)**.

## 9. 콘텐츠 생성 파이프라인

1. **PDF 파싱**: Python + PyMuPDF로 T6~9 텍스트·빈칸(`____`) 추출. (T5는 기존 데이터 추출)
2. **빈칸 채우기**: PDF 문맥 + **카카오 실제 수업답 우선**, 부족분은 마케팅 이론(교재/논문/일반이론) 조사로 보강.
3. **문제·이론 생성**: 토픽별 **병렬 에이전트**로 question/theory JSON 생성(중간 때 방식).
4. **검증**: 카카오 빈칸답과 1:1 대조, PDF 빈칸 누락 점검, 사례 포인트 반영.
5. **출제예상도**: stars 분류(5 필수~3 보통), 저빈출 정리.

## 10. 배포

- GitHub Pages(master root). `index.html` = 기말앱 진입점.
- PWA: `manifest.json`/`sw.js` 기말용 갱신(이름/아이콘/캐시 버전).
- Supabase anon key는 클라이언트 노출(정상) — 데이터 보호는 RLS로.

## 11. 비범위 (YAGNI)

- 비밀번호 재설정/이메일 인증/소셜 로그인(소규모·간단 로그인이므로 제외).
- 관리자 페이지, 문제 편집 UI(콘텐츠는 repo JSON 직접 수정).
- 실시간 협업/랭킹(단순 진도 동기화만).
- 서버리스 함수·자체 백엔드(Supabase로 충분).

## 12. 성공 기준

- 로그인 후 폰↔PC 진도가 동기화된다.
- T5~9 이론·빈칸·문제·사례가 채워져 시험 대비가 가능하다(카카오 빈칸답 정확 반영).
- 모바일에서 부드럽고, 중간앱보다 명백히 높은 품질로 보인다.
- 6/16 시험 전 배포·사용 가능.
